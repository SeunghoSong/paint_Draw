# 로그 보관 기간 정책

목적: 로그를 얼마나 보관할지 정해서 스토리지 비용과 장애 분석 가능 기간 사이의 균형을 맞추고,
개인정보 관련 이슈가 없는지 확인하는 것.

## 현재 상태 (코드 기준) — "기간" 기반이 아니라 "용량" 기반 회전

이번 예외처리 작업(3번 항목)에서 `docker-compose.yml`에 추가한 로그 설정은 다음과 같다
(3개 컨테이너 전부 동일):

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"
```

이건 **레벨별로 몇 일 보관**하는 정책이 아니라, 컨테이너당 로그 파일을 10MB씩 최대 3개
(총 30MB)까지만 남기고 그 이상은 오래된 것부터 삭제하는 **용량 기반 회전**이다. 게다가
DEBUG/INFO/WARNING/ERROR 로그가 전부 같은 파일에 섞여서 쌓이기 때문에, "특정 레벨만 며칠
보관한다"는 개념 자체가 지금 인프라 구조로는 적용되지 않는다. 실제로 며칠치가 남는지는
트래픽량에 따라 달라진다(트래픽이 많으면 30MB가 금방 차서 보관 기간이 짧아짐).

**레벨별로 다른 보관 기간을 실제로 적용하려면 중앙 로그 저장소(Loki/ES 등, 아래
[06-log-collection-architecture.md](06-log-collection-architecture.md) 참고)가 필요하다.**
지금은 그게 없으므로, 아래 "목표 정책"은 향후 로그 수집 아키텍처를 도입할 때 적용할 기준으로
남겨둔다.

## 목표 정책 (중앙 로그 저장소 도입 시 적용)

| 레벨 | 보관 기간 |
|---|---|
| DEBUG | 3일 |
| INFO | 30일 |
| WARNING | 30일 |
| ERROR 이상 | 90일 |

## 개인정보 관련 검토

**결론: 현재 로그에는 얼굴 이미지/영상 원본이 전혀 남지 않는다.** 코드를 직접 확인한 결과:

- 모바일에서 서버로 전송되는 원본 프레임(base64 JPEG)은 `Web_Server`가 `Video_Engine`으로
  중계만 할 뿐, 어떤 로그 필드에도 기록되지 않는다.
- `Video_Engine`이 추출하는 손 랜드마크(21개 좌표)도 로그에는 **개수(`count`)만** 남고
  실제 좌표값은 남지 않는다 (`landmarks_extracted`의 `detail: {"detected": true, "count": 21}`).
- `Motion_Engine`의 `gesture_computed` 로그도 동작 이름(`action`)만 남고 좌표는 없다.
- 애초에 얼굴 인식이 아니라 손 랜드마크 기반 제스처 인식이라 얼굴 이미지 자체를 다루지 않는다.

**이걸 앞으로도 지켜야 할 불변 규칙으로 명시한다: 원본 프레임 이미지나 랜드마크 좌표
원본값을 로그의 `detail` 필드에 절대 추가하지 말 것.** 디버깅을 위해 좌표를 남기고 싶다면
개수/통계값(예: 평균 이동 거리)으로 가공해서 남긴다.

이 저장소에는 별도의 개인정보 처리방침 문서가 확인되지 않았다. 만약 조직 차원의 개인정보
처리방침이 별도로 존재한다면, 위 "얼굴/영상 데이터가 로그에 남지 않는다"는 사실을 그 문서와
연결해서 명시해야 한다 (`TODO(사람이 확인): 조직의 개인정보 처리방침 문서 링크`).

## 보관 기간 경과 후 삭제 방식

- 현재(json-file 드라이버): `max-file`/`max-size` 초과 시 Docker가 오래된 파일을 자동으로
  덮어씀 — 별도 설정 불필요, 이미 적용됨.
- 중앙 저장소 도입 후: 저장소의 TTL 설정(Loki의 `retention_period`, ES의 ILM 정책 등)으로
  위 "목표 정책" 표를 그대로 적용 — 구체적 설정은 저장소 선정 후 작성 (`TODO`).
